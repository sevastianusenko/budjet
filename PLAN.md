# Hearth — семейный бюджет. План проекта

Дата: 2026-10-29. Цель: простое, красивое и «умное» приложение семейного бюджета
для американских семей. Несколько пользователей, один общий бюджет, видно кто внёс запись.
Хостинг: Vercel. Основное устройство: телефон.

---

## 1. Что показало исследование

### 1.1 Популярные приложения: за что любят и за что ругают

| Приложение | За что любят | За что ругают |
|---|---|---|
| YNAB ($109/год) | Метод «каждый доллар имеет работу», «истинные расходы» (копить на редкие траты помесячно), сообщество, реально меняет привычки | Цена, крутая кривая обучения, обязательная привязка банка |
| Monarch ($99/год) | Чистый современный интерфейс, общий дашборд для пары, net worth | Цена, медленная синхронизация банка, ошибки категорий |
| Copilot ($95/год) | Самый красивый дизайн, отзывчивые разработчики | Только iOS |
| EveryDollar | Простой zero-based, бесплатный ручной ввод | Премиум дорогой, «заточен» под метод Рэмзи |
| Goodbudget | Конверты, бесплатно, партнёры делят конверты | Устаревший интерфейс, лимит конвертов |
| PocketGuard | Одна цифра «In my pocket» (сколько можно потратить после счетов и целей) | Слабая детализация категорий |
| Honeydue | Бесплатно, для пар, можно выбрать что показывать партнёру | Мало функций |

Выводы, которые ложатся в продукт:
1. **Одна главная цифра** — «сколько безопасно потратить» — самый любимый паттерн (PocketGuard, YNAB «available»).
2. **Zero-based-lite**: план по категориям + проверка «всё ли распределено» даёт 80% пользы YNAB без его сложности.
3. **Ручной ввод — это фича, а не недостаток** для цели «приучить тратить умно»: осознанность, учёт наличных, приватность, нет сломанных синхронизаций. Банковскую синхронизацию (Plaid) в v1 не делаем.
4. **Для пар критично**: отдельные логины, общий дашборд, видно кто внёс (атрибуция), фильтр по человеку, «свои деньги» (fun money) каждому.
5. **Цена** — главная жалоба на всё платное. Наше — своё и бесплатное.
6. **Красота** решает (Copilot/Monarch), но «функционально, а не декоративно».
7. Люди боятся lock-in → экспорт CSV обязателен.

### 1.2 Что советуют эксперты (и что из этого считать в приложении)

- **50/30/20** (Элизабет Уоррен): 50% нужды, 30% желания, 20% сбережения от чистого дохода. Стартовая точка, а не догма; при высоких расходах на жильё — 60/20/20. В приложении: категории помечены Need / Want / Savings, показываем факт vs цель, цель настраивается.
- **Pay yourself first**: сбережения — первый «счёт» месяца, 10–20% дохода. В приложении: цели с плановым месячным взносом, они вычитаются из «безопасно потратить».
- **Подушка безопасности** 3–6 месяцев базовых расходов. В приложении: отдельная цель Emergency Fund и индикатор «месяцев покрытия».
- **Sinking funds / true expenses**: редкие большие траты (страховка, ремонт машины, праздники) копятся помесячно. В приложении: цели + категории с переносом остатка (rollover).
- **Структура расходов средней американской семьи** (BLS Consumer Expenditures 2024, $78.5k/год): жильё 33%, транспорт 17%, еда 13% (дома 8%, вне дома 5%), страхование и пенсия 12.5%, здоровье 8%, развлечения 4.6%, одежда 2.5%, образование 2%. Используем для **стартового плана по доходу** и для подсказки «ваша еда вне дома 12% — у среднего американца 5%».

## 2. Концепция продукта

**Hearth** — общий бюджет семьи в телефоне. Три действия: *Запланировать → Записать → Накопить*.

Принципы:
- Записать трату — 3 касания (сумма → категория → сохранить). Кто внёс — определяется автоматически.
- Один экран отвечает на вопрос «можно ли сегодня это купить?».
- Каждая цифра объяснима: рядом кнопка «как посчитано».
- Красиво, но без декора ради декора. Светлая и тёмная тема.

### 2.1 Экраны (нижняя навигация, 5 вкладок + FAB «+»)

1. **Home** — переключатель месяца; герой-цифра *Safe to spend* (на месяц и в день); полоса Income / Spent / Saved; кольцо 50/30/20; «пульс» категорий (топ-5 с прогрессом и темпом); ближайшие счета; последние записи с цветной меткой участника.
2. **Activity** — лента по дням, поиск, фильтры: участник, категория, тип. Тап — редактирование. Удаление с Undo.
3. **Plan** — бюджет месяца по группам Needs / Wants / Savings: план vs факт, прогресс и темп («к 20-му числу должно быть потрачено ≤ 65%»). Сверху «Unassigned» — сколько дохода не распределено (zero-based проверка). Кнопка «Copy last month». Rollover по категории.
4. **Goals** — цели: сумма, срок, накоплено, «нужно в месяц», ETA при текущем темпе. Emergency Fund показывает месяцы покрытия. Кнопка «Add money».
5. **Insights** — графики за 6–12 месяцев: расходы по категориям (стек), доход vs расход, savings rate, 50/30/20 во времени, вклад участников, сравнение с 3-месячным средним и с BLS.
- **Settings** — семья (название, инвайт-код), участники и цвета, категории, повторяющиеся счета, экспорт CSV, тема.

### 2.2 Ввод записи (главный поток)
Bottom sheet: переключатель Expense / Income / To goal → крупная клавиатура суммы → чипы категорий (частые первые) → дата (Today / Yesterday / выбрать) → заметка (опционально) → Save. Кто внёс — текущий пользователь (можно переключить «paid by»). После сохранения — тост с Undo.

### 2.3 Мультипользователь
Household → участники с собственными логинами и **цветом**. У каждой записи цветная полоска/точка автора. Фильтр по участнику в Activity и Insights. Инвайт по 6-символьному коду. Роли: owner / member (owner удаляет участников).

## 3. Формулы («умная» часть, все в `src/lib/calc.ts`, с тестами)

Обозначения: месяц M, день d, дней в месяце D, осталось дней R = D − d + 1.

- **Planned expenses** B = Σ planned по расходным категориям.
- **Spent** S = Σ expense-транзакций за M.
- **Planned savings** G = Σ плановых месячных взносов целей; **Contributed** C = Σ транзакций «to goal» за M.
- **Expected income** I = план дохода (если есть) иначе факт дохода за M.
- **Unassigned** = I − B − G (zero-based проверка; цель = 0).
- **Safe to spend (month)** = Σ по вариативным категориям (planned − spent), только положительные остатки, минус перерасход в фиксированных. **Per day** = / R.
- **Pace** по категории: expected_by_today = planned × d/D; статус: on track / ahead / over.
- **Projected month-end spend** = S + (вариативные траты за последние 14 дней / 14) × R.
- **Savings rate** = (Income − Expenses) / Income, где взносы в цели считаются сбережением; скользящее за 3 мес.
- **50/30/20 actual** = доли Need / Want / (Savings + goal contributions) от дохода месяца; сравнение с настраиваемой целью.
- **Emergency months** = saved(Emergency goal) / avg monthly Needs за 3 мес.
- **Goal monthly needed** = (target − saved) / months_to_deadline; **ETA** = (target − saved) / avg contribution за 3 мес.
- **vs 3-mo average** по категории = spent_M / avg(spent за 3 предыдущих) − 1.
- **vs BLS**: доля категории от расходов vs доля у среднего американского домохозяйства (таблица в коде).

Инсайты (правила, не ИИ): перерасход темпа, категория > 3-mo среднего на 25%+, подушка < 3 мес, unassigned ≠ 0, savings rate < 20%, лучший/худший месяц.

## 4. Архитектура

- **Next.js (App Router) + TypeScript + Tailwind v4**, React Server Components + Server Actions. Один проект, деплой на Vercel.
- **БД: Postgres**. Прод — Neon через Vercel Marketplace (`DATABASE_URL`). Локально без БД — **PGlite** (встроенный Postgres на WASM, файлы в `.data/`), та же схема и миграции Drizzle. Переключение по наличию `DATABASE_URL`.
- **ORM: Drizzle** (миграции SQL в репозитории).
- **Auth**: email + пароль, bcrypt (cost 12), сессия — подписанный JWT (jose, HS256) в httpOnly cookie, 30 дней. Без внешних сервисов. Защищённые роуты через проверку в layout.
- **Графики**: Recharts. **Иконки**: lucide-react. **Шрифт**: Inter через next/font.
- **PWA**: manifest + иконки + theme-color → «Add to Home Screen» на iPhone/Android.
- **Деньги** — целые центы. **Даты** — строки `YYYY-MM-DD`, выбираются на клиенте (нет проблем с часовыми поясами).
- **Экспорт CSV** — серверный роут.

Схема данных: households, users, categories (kind, group need/want/savings/income, rollover), budgets (category × month → planned), transactions (type expense/income/goal, user_id, category_id, goal_id, recurring_id, amount, date, note), goals (target, deadline, monthly_plan, is_emergency), recurring (bill: name, amount, day, category, active).

## 5. Самокритика первого варианта плана и исправления

| Было в первом варианте | Проблема | Решение |
|---|---|---|
| Синхронизация с банками (Plaid) | Платно, сложно, ломается, противоречит цели «осознанные траты» | Убрано. Ручной ввод за 3 касания + повторяющиеся счета «Mark paid» |
| Net worth / инвестиции | Другая задача, раздувает v1 | Убрано. Только цели и подушка |
| «ИИ-советы» | Непредсказуемо, дорого, пользователи не доверяют цифрам без объяснения | Правило-инсайты с прозрачными формулами и кнопкой «как посчитано» |
| Полный YNAB zero-based с конвертами и переносами | Крутая кривая обучения, люди бросают | Zero-based-lite: план по категориям + «Unassigned» + rollover по желанию |
| Auth.js (beta) с Google-логином | Зависимость от бета-версии и настройки OAuth у пользователя | Своя простая email+пароль авторизация, JWT cookie |
| Локальная разработка требует Postgres | Нельзя проверить без настройки БД | PGlite локально, Neon в проде, один код |
| Мультивалюта, чеки-фото, пуш-уведомления, оффлайн | Не критично для первых пользователей | В бэклог v2 |
| Стартовый пустой бюджет | Пустой экран убивает мотивацию | Онбординг: доход → автоплан по 50/30/20 и долям BLS, редактируемый |
| Нет экспорта | Страх lock-in | CSV экспорт в v1 |
| Нет Undo при удалении | Ошибки на телефоне часты | Toast с Undo |

Риски после исправлений: самописная авторизация (минимизирована: bcrypt, httpOnly, secure, sameSite; без reset пароля в v1); PGlite + Turbopack — проверить, fallback: `DATABASE_URL` на Neon сразу.
